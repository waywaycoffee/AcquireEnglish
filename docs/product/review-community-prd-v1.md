# 复习与社区产品需求确认稿

版本：V1.0　日期：2026年11月20日　状态：待产品确认

本稿定义复习、一起练社区及个人形象体系的目标行为，供确认后分期开发。文中“首期”表示建议范围，不表示已经实现；示例数字和奖励参数不等于正式运营规则。

## 1 产品定位与确认范围

复习解决“把自己学过的视频、收藏词句和背过的词真正记住”。社区解决“知道搭子在学什么、一起检验记忆、用共同进步维持学习兴趣”。学习数据驱动互动，互动再回到真实学习。

用户已明确的要求：

- 复习与本人视频、收藏单词、背词和短语有可见关联。
- 一起上学是查看对方近期视频、学习时长和动态，不再用共同旅行代替这个模块。
- 单词PK用近期实际学习的单词比赛记忆。
- 大比武是学习数据加随机变量驱动的双人卡通战斗，具有动作、血条和文字播报。
- 图书馆比较共同与不同的收藏，并大致比较词汇量。
- 个人形象为2D卡通，提供少年和青年、男性与女性风格；自然肤色，无老年或绿色脸。
- 背包管理已有物品，商店用于获取装扮，支持个人形象与同桌空间装扮。

待确认的方案选择集中在第13节；未确认前不将建议数值写成正式承诺。

## 2 当前基础与待开发边界

| 范围 | 当前基础 | 本稿要求的增量 |
| --- | --- | --- |
| 复习 | FSRS、单词/短语/句子、原句与视频来源、自由练习、部分来源展示 | 来源筛选与定向复习、今日任务层级、完整完成反馈、同步和中断状态 |
| 社区内容 | 视频分享、组队邀请、反馈、点赞、评论、热门、榜单 | 公开学习卡、可靠导入、关注收藏、通知、内容治理 |
| 搭子 | 相似用户、社区资料与寻找搭子状态 | 双向邀请、共同空间、可撤销的数据共享 |
| PK | 现有词汇挑战接口 | 近期学习题库、真正答题计分与复盘；不能把已有挑战接口视为完整比赛 |
| 学习与奖励 | 学习统计、积分及会员券相关基础 | 可信学习事件、奖励账本、领取和反重复规则 |
| 形象 | 衣柜商城、积分兑换、几何人物预览 | 精细角色、分层服装、坐姿与战斗动作、一致的个人形象 |
| Pencil | 多个页面、示例角色与流程设计 | 转为实际交互；部分自习室场景仍待生成，插画不等于可换装动画资源 |

社区全景预览的mock点赞、关注与活动不能当成正式持久化功能。正式冷启动只使用标明身份的官方内容和真实内测用户，不伪造活跃人数。

## 3 导航与核心闭环

底部保留现有主导航，不再为每个玩法增加一级入口。

- 复习首页：今日计划、继续复习、学习来源、薄弱项、背词入口、复习设置。
- 社区：发现、一起练、消息；榜单放在一起练的次级入口。
- 一起练大厅：我的同桌、一起上学、单词PK、大比武、图书馆、打卡、背包与商店。
- 我的：个人资料、个人形象、共享设置、奖励记录。

个人闭环：视频学习 → 主动收藏词句 → 到期复习 → 反馈掌握情况 → 更新计划。

双人闭环：邀请搭子 → 双方同意 → 查看学习近况 → 各自学习 → 打卡 → PK/图书馆/趣味战斗 → 获得反馈与装扮 → 再次学习。

外部获客：分享公开学习卡 → 无需登录看来源与体验 → 注册保存结果 → 加入一起练。不得分享私有文件地址或在保存前强制付费。

## 4 统一数据口径

### 4.1 学习事件

区分“视频播放”“有效学习时长”“完成复习次数”“不同词条数”。播放原视频8分钟、反复精听18分钟时，两种时长分别标注，不混为视频长度。

有效学习事件记录用户、会话、来源、内容ID、起止时间、有效秒数、事件类型、设备、去重键和规则版本。前台播放/有效交互心跳可计入，暂停、后台挂机、同时多设备重叠部分不重复计时。离线数据先记为待核验，不能立即发可交易奖励。

复习次数可包含重复练习；学习数量用于奖励和战斗时，建议采用周期内去重词条数，并区分新学与复习。浏览释义、打开页面、拖动进度条不计完成。跟读与播放器同时进行不双倍计时。

### 4.2 周期与归属

建议首期使用北京时间自然日，日界为00:00，周一开始新周；所有页面标注周期。视频和收藏归属本人；共享的是有限视图，不转移原始资产权限。删除收藏后停止新的复习安排，但可保留不含原文的统计历史。

### 4.3 保存与多端

本地学习结果优先可靠保存，云同步使用幂等事件。明确显示已保存、本地已保存待同步、同步冲突与保存失败。多设备旧评分不能覆盖较新记录；冲突后重新计算队列。所有奖励、比赛、装备与公开操作以服务端状态为准。

## 5 复习模块详细需求

### 5.1 内容来源与入队规则

| 来源 | 进入方式 | 展示来源 | 对计划的影响 |
| --- | --- | --- | --- |
| 视频收藏单词 | 本人在播放器主动收藏 | 课程、集数、原句、时间点 | 进入个人FSRS队列 |
| 收藏短语/句子 | 主动收藏或加入短语库 | 原文、释义、关联视频；无视频则标记手动收藏 | 进入相应类型队列 |
| 推荐背词 | 用户选择背词计划并开始学习 | 词库/计划名称，不伪装成视频来源 | 按该计划的队列规则处理 |
| PK遇到的词 | 赛后用户确认收藏或加入计划 | PK来源与公开词典例句 | 未确认前不自动进入 |
| 对方图书馆词汇 | 查看后本人确认收藏 | 对方公开收藏推荐，不复制其私有视频语境 | 成为本人的新收藏 |

同一词元多次出现时保留多条来源，但不要因多个视频生成重复单词卡；短语和单词分别建身份。首期沿用现有卡片ID和FSRS记录，迁移不得清空历史。来源被删除时词条仍可用，但显示“原视频已不可用”，禁用跳转。

### 5.2 复习首页

首屏依次显示标题、今日到期数、新学可用数、预计时长和主按钮；不能让统计把主按钮挤到手机首屏以外。预计时长使用个人历史或明确默认估计，显示“约”。

有未完成会话时主按钮为“继续复习”；无会话但有计划时为“开始今日复习”；无到期时提示下一次时间，提供自由练习；没有收藏时引导去课程或收藏内容。

“从你学过的内容中复习”按视频/词库分组，显示标题、关联单词/短语/句子数、已学数、到期数，展开查看原句和词条。提供回到原视频、复习这段内容、查看全部关联内容。视频筛选后，计划复习只取该来源当前可学项；提前练习必须明确标为自由练习。

提供全部/单词/短语/句子、收藏来源/背词计划筛选。分类数量说明是“收藏总量”还是“今日任务”，不能混用。周历使用真实完成记录，不制造连续天数压力。

### 5.3 计划生成

保留FSRS。到期优先，沿用现有“到期与新学穿插”规则，首页用通俗文字说明。每日新学上限只控制新学，到期不受限；上限为0表示暂停新学，不表示关闭复习。

选择来源/类型只改变本次范围，不修改未选卡片的到期时间。已完成后出现新的到期卡，应允许同日继续；不能因当天已完成一次而锁住全天。预测下次间隔取自当前卡片和当前阶段，不写死天数。

### 5.4 练习页与答案页

顶部显示模式、当前条目/本轮总数、已完成进度与稍后继续。新词多阶段通过次数与卡片完成数分开标注，避免把3次通过当成3个词。

答案揭示前显示题目、回忆指引与可用来源，不泄露释义。可播放原句和回看视频，并提示这些操作可能提供答案。揭示后显示释义、原句、中文、发音、来源和回看入口。

计划复习评分为忘记、吃力、记得、很轻松，每项配描述及实时预测间隔。用户点击后进入保存中，禁止重复点击，保存成功才完成并切下一条。自由练习不写FSRS、不消耗新学额度，但可记录独立练习统计。

识别、拼写、跟读等既有多阶段设置继续保留。取消拼写或拒绝麦克风不能伪造通过；云评分失败给出重试/自评，不把网络故障算成遗忘。多阶段评分失败后重试不得重复累加阶段结果。

### 5.5 完成页与薄弱项

显示本轮实际完成数量、新学/到期分类、有效用时及评分分布；没有足够数据时不显示“掌握率”。忘记和吃力项进入可选薄弱练习列表，自由再练不改变刚保存的计划。

提供返回概览、继续剩余到期内容、自由巩固、预览成果卡。分享文案先预览可编辑，默认不含录音、具体收藏、私人课程；用户选可见范围并确认后才发布。失败保留草稿，不显示已发布。

### 5.6 设置与异常

设置包含每日新学上限、类型范围、练习模式、提醒时间。首期不开放容易误用的FSRS高级参数。通知权限拒绝不阻断学习。

| 状态 | 页面反馈 | 处理 |
| --- | --- | --- |
| 首次无内容 | 说明收藏与入队关系 | 去学习/去收藏 |
| 新学已暂停 | 到期照常，新学为0 | 调整设置 |
| 没有到期 | 显示下次到期或暂无计划 | 自由练习 |
| 未完成退出 | 已完成保留，未评分仍待学 | 继续/退出 |
| 本地保存失败 | 当前卡与答案不丢失 | 重试，不切卡 |
| 云同步失败 | 本地已保存，待同步 | 不阻塞本地复习 |
| 视频失效 | 卡片可练，来源标不可用 | 禁止失效跳转 |
| 收藏被另一端删除 | 提示并移出当前队列 | 不继续写旧评分 |

## 6 社区内容与同桌关系

### 6.1 发现与帖子

保留视频分享、组队、反馈；逐步支持学习打卡、方法、问答。帖子显示作者个人形象、水平、来源、适合人群、学习入口与讨论。核心操作为去学习、收藏去学、我也练过、评论和点赞。“我也练过”由真实学习记录支持，不等同点赞。

视频分享校验公开来源。内容下架、源视频失效、导入失败均提供真实状态。发帖、评论、邀请限流，支持举报、拉黑、删除和审核；正式扩展开放发布前先完成治理基础。

### 6.2 搭子邀请

建议首期一人只有一位正式同桌，允许关注多人。待确认邀请不锁定席位；接受时服务端再次检查双方关系。流程：无同桌→发邀请/收邀请→接受/拒绝/撤回/过期→已组队→退出/解除。

接受前说明共享内容，首期默认不公开具体视频和收藏明细，由本人主动开启。解除或拉黑立即停止后续数据访问和提醒；个人学习、装备和积分保留。旧比赛按当时授权快照与保留规则处理，不继续暴露实时数据。

首期用鼓励贴纸和系统事件代替自由私信；邀请与鼓励通知可关闭，禁止无限催促。

## 7 四个核心一起练模块

### 7.1 一起上学

定位是搭子学习近况，不是旅行关卡。

展示近7/30天有效时长、学习天数、近期视频、完成复习数量；按天筛选。视频卡包含标题、课程/集数、学习日期、有效时长、原片长度和公开内容入口。不能把“看过3个视频”标成“学会3个视频”。

本人可分别授权视频标题、时长统计和收藏概览。私有上传与受限网盘课程不对外开放链接；仅经同意显示脱敏标题。对方未授权、没学习、同步延迟是三种不同状态。

点击公开视频可打开同一来源，但不继承搭子的进度。允许发一次鼓励、邀请共同练同一段内容；不可查看未授权录音与精确作息。

### 7.2 单词PK

目的：检验双方近期实际学过的单词，赛后回到复习。

建议首期为好友异步10题，近期范围默认7天，可扩大至30天。词条需要有实际学习/复习事件；仅收藏未学习的不算“近期已学”。优先共同学过的单词。不足10个时提供5题局、扩大时间范围，或明确双方同意用各自近期词的并集；不静默替换为陌生公共词库。

同一局使用同一题组。首期建议释义四选一，后续听音/拼写分别建模式。错项必须可靠且不出现两个正确选项。题库、答案、版本和随机种子由服务端保存，提交前不下发可直接读取的答案。

建议先按正确数比较，同分平局；用时作为参考，不以网络快慢决定胜负。超时未答、不退出刷题、断线恢复均有规则。题组不足不创建无效比赛。

生命周期：邀请→接受→题组冻结→双方分别作答→等待对方→结算→复盘。邀请建议24小时过期，接受后建议24小时完成；对方未完成显示待完成/超时，不假装“记忆不如你”。

结算显示双方正确数、逐题结果、释义、个人可见来源及再次练习。错词由本人确认后加入收藏；已在FSRS的卡片不因比赛一次答错直接修改计划。PK与个人计划复习分开计数。

### 7.3 大比武

定位：学习积累转成两个个人虚拟人的趣味动画，独立于单词答题PK。不能宣称战力等于真实英语能力。

建议属性取最近7天经过核验的学习快照。初始血量一致100。有效时长形成攻击，去重完成词句形成防御，有效学习天数形成稳定加成。服装、付费会员不提高属性。

待确认的首版公式：M为有效分钟，上限210；N为完成的不同词句数，上限140；D为学习天数，上限7。攻击=10+6×√(M/210)，护甲=2+4×√(N/140)，稳定加成=D/7。每次伤害=max(3,四舍五入((攻击−对方护甲+稳定加成)×U))，U在0.9至1.1间。每回合各行动一次，先手轮换；最多12回合，剩余血量相同比较为平局。公式仅为可测试初值，内测后调平衡。

建议首期不加暴击和闪避，先把随机伤害和格挡表现做清楚。格挡只是护甲减伤的动作表现，不能播报后再次扣减伤害。文字显示原始攻击、减伤和实际扣血，血条与日志相符。

动作包含待机、向前、出手、受击/格挡、返回、胜利/平局。每步约0.4至0.8秒，支持倍速、跳过动画和减少动态模式。用非血腥夸张动作；先做位移/缩放/姿态切换，不把尚未制作的全套骨骼动作列为首期已具备。

服务端生成一次对局结果、回合日志和随机种子，回放不重掷；双方看到同一结果。不押注积分、不收费复活。任一方近期完全无有效学习时，引导学习或试打不计奖。

### 7.4 图书馆

展示双方授权的收藏词总数、共同收藏、仅我收藏、仅对方收藏，词元去重，单词和短语分开。交集和差集必须满足各自总数关系；分页、搜索和收藏更新均反映真实数据。

词条可看公开词典释义。我的收藏可显示我的视频语境；对方私有来源不随词条泄露。收藏对方词条需本人确认，成功后从“仅对方”更新为“共同”，但不复制其FSRS历史。

词汇量分两层：收藏词数/复习词数是可直接统计值；“估计词汇量”只来自同一版本的分级测评，显示日期、区间和测评口径。没有测评显示尚未测评；收藏少不等于词汇量小，不从收藏数编造估计值。

私密、仅同桌、公开三种共享范围建议首期只做私密/仅同桌。撤销共享后停止明细访问，缓存失效，不继续展示旧列表。

## 8 打卡与奖励

建议每日完成条件为：完成当日可用到期复习中的最多5条，或完成至少10分钟有效课程学习；两条路线任选。当天没有到期卡时不逼用户新增收藏。具体门槛见确认项。

完成任务后用户确认打卡，服务端核验，写入唯一的用户+日期记录，再发奖励。个人打卡不依赖搭子；双方都完成时增加共同天数。不要把打开页面当完成，也不自动发公开帖子。

建议积分奖励每日一次10分、共同打卡每人额外2分；连续或累计7天的指定基础装扮为确定奖励。积分价格和收益先内测再确认，首期不加购买型补签。会员时长/抵扣券沿用独立券规则，不和衣柜积分合并为同一种货币。

状态为未满足→可打卡→核验中→已打卡待领取→已领取；奖励失败可补发但不能重复。离线、跨日、退款/异常奖励撤销都有账本记录，不能只改余额。

## 9 个人形象 背包与商店

### 9.1 基础人物

只做少年/青年角色，男性/女性为风格筛选，不要求真实年龄或生日，不限制自由选择。首批建议6个角色，均免费；自然肤色，禁止显老、绿色脸或无意的肤色偏移。

素材统一竖版3:4、3头身、自然站姿和统一脚底基线。角色在画布中占高约80%至85%，透明背景素材与界面背景分离。另做同桌坐姿、打斗姿态，不能把站姿拉伸成坐姿。商店缩略图与实际装备预览一致。

### 9.2 装备与资产

背包分类：人物、发型、上衣、下装、配饰、同桌空间、名牌、道具。每个物品有归属、槽位、稀有度展示（如采用）、资源版本和兼容范围。肤色和年龄不加价。

先试穿→撤销/换件→保存。预览不是已装备，保存成功才同步各页面。更换人物时检查服装兼容，不能静默吞掉已购资产；不兼容则提示换回基础款。

首期朴素服装为主：纯色卫衣、针织衫、衬衫、直筒裤和运动鞋。复杂主题套装后置。整套人物插画只是模板预览；单件换装必须有统一身体、手臂、衣服和前景遮挡层。

### 9.3 获取与交易

免费领取、学习解锁、积分兑换三种先上线，现金装扮后置。商店展示物品详情、兼容角色、价格、余额和预览。兑换前二次确认；余额不足、重复拥有、并发购买与扣款成功装备失败分别处理。已经拥有的永久服装不允许重复收费。

道具只用于鼓励、摆件和合照，不提高PK答案正确率，不伪造学习记录，不改变复习算法。现金商城须完成支付到账、退款与资源回收规则后才能开放。

## 10 通知 隐私与内容治理

通知包括搭子邀请、接受/退出、PK邀请和结算、评论回复、奖励到账；同类聚合，自己操作不通知自己。鼓励/提醒建议每对搭子每天最多1次，用户可关闭。没有自由私信时不要展示可输入但不可发送的假入口。

共享授权页列明：近期视频标题、按天聚合时长、收藏词明细、测评结果。默认关闭具体内容明细；同意组队不等于同意所有共享。拉黑、撤销授权与删除账号时更新关联权限。

用户可举报帖子/评论/人物名/骚扰邀请，后台有待处理、处理、驳回、申诉状态和审计。运营能下架内容但普通用户不能调用管理接口。示例数据只能在演示模式，不进入排行榜、奖励或增长统计。

## 11 数据模型与验收

### 11.1 必要实体

沿用复习记录、收藏、课程、社区帖子和现有资产表，增量包括：学习事件/会话、同桌关系与邀请、共享授权、PK题组与逐题提交、大比武快照与回合日志、打卡与奖励账本、装备草稿与已保存搭配、通知与举报。

主键幂等：用户+会话事件；对局+用户+题号；对局结算；用户+日期打卡；用户+奖励规则+达成事件；用户+永久物品所有权。客户端不能提交“胜利”“已支付”“打卡有效”直接发奖。

### 11.2 验收用例

| 模块 | 必须跑通的场景 |
| --- | --- |
| 来源复习 | 视频收藏后可定位；取消收藏停止安排；同词多来源不重复卡 |
| 评分 | 答案不提前露出；双击不重复计次；失败不切卡；自由练习不改FSRS |
| 多端 | 本地保存云失败可恢复；旧设备不覆盖新记录 |
| 同桌 | 双向同意；重复接受不多建关系；撤销授权后API不可读取 |
| 一起上学 | 私有视频链接不泄露；有效时长与原片长度区分；无权限不显示0 |
| 单词PK | 双方同题；无足够词可退；断线恢复；答案不可提前读；同分规则一致 |
| 大比武 | 血条和日志一致；相同快照与种子可重放；装扮不加战力；跳过动画不改结果 |
| 图书馆 | 交差集数学一致；词元去重；收藏后列表更新；未测评不造词汇量 |
| 资产奖励 | 并发兑换不负余额；重复领取不重复入账；预览不扣费；失败保留原装备 |
| 治理 | 拉黑即停邀请；举报可跟踪；mock不计奖励和排名 |

### 11.3 体验要求

手机首屏能看到主要行动，平板使用居中内容和侧边统计。长列表分页；加载、空态、错误、未授权分别设计。支持大字号、语音控件可读标签、减少动态模式；颜色不是区分胜负和掌握状态的唯一信号。

## 12 分期与衡量

| 批次 | 可交付范围 | 发布前提 |
| --- | --- | --- |
| A 个人学习闭环 | 来源复习、定向练习、可靠保存、真实完成反馈 | 不丢现有进度，复习回归测试通过 |
| B 双人数据闭环 | 搭子关系、授权、一起上学、图书馆、基础角色与背包 | 双账号越权及解除关系测试通过 |

衡量：首次有效学习转化、到期任务完成率、来源入口使用率、搭子双向接受率、共同有效学习天数、PK完成率、图书馆收藏转化、7日/30日学习留存。分享、点击、点赞不是学习效果本身。先采集基线再定目标，不承诺未经验证的增长率。
